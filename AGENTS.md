# StudyLanguage

- Static Japanese study app for Korean speakers: TypeScript, Vite, Vitest, DOM views and hash routes.
- From this repository in PowerShell with Node/npm installed: `npm test` runs Vitest; `npm run build` runs TypeScript checking and Vite production build; `npm run dev -- --host 127.0.0.1` starts local development.
- `src/vocab/vocab-view.ts` owns vocabulary routes, cards and delegated actions. Reuse its cards and SRS storage for additional learning views.
- `src/vocab/vocab-quiz-view.ts` owns `#/vocab/quiz` routes, before notebook fallback in `src/main.ts`. `vocab-quiz-logic.ts` must keep exactly five unique nonoverlapping choices, exclude all meanings sharing the prompt reading, and avoid repeated readings per round. Fold katakana only for comparison: prompts show the real spelling with furigana, and choices keep katakana. Save only the first answer through shared vocabulary SRS helpers; do not dispatch a refresh that resets the active round.
- Quiz reverse direction uses `?direction=ko-ja` in the hash, including the picker route. Preserve it through scope links/retry/restart; use distinct kana choices (katakana stays katakana) and exclude overlapping Korean meanings, and deduplicate Korean prompts. Default Japanese-to-Korean behavior stays backward compatible.
- Preserve vocabulary IDs, ordering and existing SRS keys when enriching metadata. IDs are opaque record keys: change a spelling only through a reviewed `japanese` override, never the ID. Do not re-scrape merely to fix readings or add classifications.
- `scripts/build-vocabulary.ts` is the source acquisition pipeline; dictionary inputs live in ignored `scripts/vendor/`. Reading/classification enrichment must be shared with this pipeline.
- For reading/POS updates, run `npm run enrich:vocab`; it reuses `scripts/vocab-metadata.ts` without scraping. JMdict headword POS takes priority over token analysis for unambiguous forms; use `scripts/vocabulary-overrides.json` for reviewed homophones, counters, irregular readings and particle sounds (`spoken`). Do not infer kana noun classes from isolated tokenization alone.
- Concatenated token readings are provisional for mixed-script compounds/counters. Compare equivalent dictionary forms (e.g. 一週間 / 一週間に, 一人暮らし / 一人ぐらし) and keep regression cases against the shipped JSON as well as the helper.
- Readings keep the surface kana (`restoreSurfaceKana`): コーヒー stays katakana, so composition practice expects katakana. Duome romaji is unreliable (pinyin in kanji words, literal は); enrichment regenerates all romaji from readings. A single-kanji reading from JmdictFurigana may be the wrong sense: check it against the Korean meaning.
- `buildFurigana` is the only aligner: ruby goes over kanji, digits and letters, never over kana. Use `renderWord` or `fillWithFurigana`; do not put a whole reading over a mixed word.
- Visual language is a Japanese station sign (`src/style.css` header). Color is meaning: green known, amber confusing, red unknown, grey new. Use tokens, kanji tiles and `src/icons.ts`, not emoji. Everything must work in dark mode and at 320px.
- DOM tests cannot verify CSS layout; inspect new screens in a browser when possible.
- Pass JavaScript to PowerShell-launched Node through a here-string/stdin or a file; inline quoting may strip string delimiters.
