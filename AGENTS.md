# StudyLanguage

- Static Japanese study app for Korean speakers: TypeScript, Vite, Vitest, DOM views and hash routes.
- From this repository in PowerShell with Node/npm installed: `npm test` runs Vitest; `npm run build` runs TypeScript checking and Vite production build; `npm run dev -- --host 127.0.0.1` starts local development.
- `src/vocab/vocab-view.ts` owns vocabulary routes, cards and delegated actions. Reuse its cards and SRS storage for additional learning views.
- `src/vocab/vocab-quiz-view.ts` owns `#/vocab/quiz` routes, before notebook fallback in `src/main.ts`. `vocab-quiz-logic.ts` must keep exactly five unique nonoverlapping choices, exclude all meanings sharing the prompt reading, and avoid repeated readings per round. Fold katakana only for comparison: prompts show the real spelling with furigana, and choices keep katakana. Each question starts with a typed answer (`checkTypedAnswer`: any listed meaning, comma-separated answers, noun + 이에요/입니다/요; predicates match any conjugation through `sameKoreanPredicate` in `src/vocab/korean-stem.ts` (재미있는/재밌어요 = 재미있다, but 재미없다/즐겁다/크기 ≠); ㄷ/ㅅ/ㅂ/르/ㅎ irregulars and 세요 included; no typo tolerance, one syllable often changes the word; one-syllable stems need a common ending; kanji prompts never accept homophone meanings; ko-ja is romaji → kana via `src/practice/romaji.ts` and must match a same-meaning reading). "보기 보기" reveals the five choices; a strict miss offers "내 답도 맞아요". Only a typed correct answer without revealing may mark an unmarked word 암기됨. Furigana in the prompt and choices stays hidden (`readings-hidden`) until 독음 보기 or an answer. Save only the first answer through `recordQuizAnswer` (src/srs.ts): a wrong answer sets `missed` (the 틀린 단어 list) and lowers 암기됨 to 헷갈림 or an unmarked word to 모름, never otherwise overwriting my own grade; a right answer clears `missed`. Card grade buttons (`reviewEntry`) and bookmarks keep `missed`; do not dispatch a refresh that resets the active round.
- Quiz reverse direction uses `?direction=ko-ja` in the hash, including the picker route. Preserve it through scope links/retry/restart; choices are distinct by reading and by spelling, shown as the real spelling with furigana (katakana stays katakana) and exclude overlapping Korean meanings, and deduplicate Korean prompts. Default Japanese-to-Korean behavior stays backward compatible.
- Quiz scope queries: `?count=all` asks every word in scope (overrides `limit`), `?only=weak` keeps my unknown/confusing marks (`isWeak`), `?only=missed` keeps quiz misses (`isMissed`); both re-filter on restart. Kanji grades are all quiz results, so `recordKanji` sets `missed` on unknown and clears it on known; `{base}/wrong` lists them and `scope=missed` re-asks them. Both work for JLPT sources too; Day/batch screens get the three buttons from `renderQuizLinks`, with the Day pager above the cards. Wrong-note, quiz picker and JLPT level screens use `renderWrongQuizLinks`: up to 10 questions, plus a whole-list round when there are more. `renderWrongNotes` draws `#/vocab/wrong` and `#/jlpt/wrong`, and their `/weak` pages list only my 모름·헷갈림 marks (a missed word I marked still shows there). `readingMissed` (읽기 모름, `/reading` pages, `?only=reading`) marks a kanji word I knew only after seeing its reading: set by a correct ja-ko quiz answer after 독음 or by opening a hidden card's furigana; cleared only by a correct quiz answer without 독음; every other record keeps it. Using 독음 also keeps an unmarked word from becoming 암기됨.
- Preserve vocabulary IDs, ordering and existing SRS keys when enriching metadata. IDs are opaque record keys: change a spelling only through a reviewed `japanese` override, never the ID. Do not re-scrape merely to fix readings or add classifications. Bad Duolingo meanings (particles, sentence fragments) get a reviewed `korean` override; fragments that are not words get `quiz: false` (kept in the notebook, never asked or offered). `cleanKorean` strips trailing full stops; for plain-form predicates it keeps dictionary forms only (fragments of the same word are dropped, ~하 → ~하다, 즐거운 → 즐겁다), for ~ます words drops cut question forms, and leaves ~か questions and adverbs alone. A reviewed `korean` override is used as written. `npm run enrich:vocab` rewrites its own input, so dropped Duolingo fragments survive only in git history (before this change); rerun from that copy when changing the rules and review the diff. Check new grading rules against every other meaning in the notebook, not just a few examples.
- `scripts/build-vocabulary.ts` is the source acquisition pipeline; dictionary inputs live in ignored `scripts/vendor/`. Reading/classification enrichment must be shared with this pipeline.
- For reading/POS updates, run `npm run enrich:vocab`; it reuses `scripts/vocab-metadata.ts` without scraping. JMdict headword POS takes priority over token analysis for unambiguous forms; use `scripts/vocabulary-overrides.json` for reviewed homophones, counters, irregular readings and particle sounds (`spoken`). Do not infer kana noun classes from isolated tokenization alone.
- Concatenated token readings are provisional for mixed-script compounds/counters. Compare equivalent dictionary forms (e.g. 一週間 / 一週間に, 一人暮らし / 一人ぐらし) and keep regression cases against the shipped JSON as well as the helper.
- Readings keep the surface kana (`restoreSurfaceKana`): コーヒー stays katakana, so composition practice expects katakana. Duome romaji is unreliable (pinyin in kanji words, literal は); enrichment regenerates all romaji from readings. A single-kanji reading from JmdictFurigana may be the wrong sense: check it against the Korean meaning.
- `buildFurigana` is the only aligner: ruby goes over kanji, digits and letters, never over kana. Use `renderWord` or `fillWithFurigana`; do not put a whole reading over a mixed word. Card lists start in 뜻 가리기 mode (`vocab-cards-hidden` on <html>; turning it off is remembered): tapping a word with furigana shows only its reading (`readings-shown`) and at once marks it 읽기 모름 (`setReadingMissed`; closing it again in the same view undoes a mark it made), the rest of the card or 뜻 보기 shows the meaning, and the grade buttons work as usual; a graded card moves to its new section at once, on PC and phone alike.
- The app is named 히토코토 (ひとこと). Visual language is flat colour fields with large type (`src/style.css` header). Screens use the full width: no content max-width; lists add columns, question screens split into left prompt and right answers from 1000px. Status colors stay reserved: green known, amber confusing, red unknown, grey new. Text stays at 14px or larger. Use tokens and `src/icons.ts`, not emoji. Everything must work in dark mode and at 320px.
- Kanji (`src/kanji/`, shown as 칸지) teaches Japanese use: Japanese glyphs and stroke order, on/kun readings and word readings come first; Korean 훈음 is only a meaning aid. Data comes from `npm run build:kanji` (vendor inputs documented in `scripts/build-kanji.ts`, reviewed meanings in `scripts/kanji-overrides.json`). Reading and writing are recorded apart in `srs-store-kanji` as `r:字` and `w:字`, and sync through `ProgressSnapshot.srsKanji`, which older records lack. Stroke data is a lazy chunk. The word-reading quiz prefers words made of kanji learned up to that set and offers misreadings of the asked kanji (学生 → まなせい, ids `misread:`) plus real words with the same first kana, never for a bare one-kanji word (生 = せい, なま). Learning write sessions take each kanji through trace, copy and recall steps and record only recall; `scope=today` is recall only. The detail page has an unrecorded free pad. Japanese text uses Noto Sans JP (Duolingo fonts are proprietary). Check meanings against standard 훈음, not the first libhangul sense.
- JLPT (`src/jlpt/`, `#/jlpt/{n5..n1}`) reuses vocabulary cards, the quiz view (`VocabQuizSource`) and the kanji view (`KanjiContext`). Data comes from `npm run build:jlpt` and `npm run build:kanji`; inputs are documented in those scripts. Levels are unofficial (Waller lists), and the app must say so. A word with the same spelling and reading as a notebook word shares its id and audio so records carry over, but not its meaning: Duolingo meanings hold conjugated fragments unfit as test answers. Reviewed meanings go in `scripts/jlpt-korean.tsv`. Do not change `j-` ids. `KANJI` stays the notebook's characters (`core`); `kanjiOfLevel` picks by level. Words load lazily: `renderJlptView` shows a loading state, then dispatches `vocab:refresh`.
- Captured phrases fill an empty reading with kuromoji in a Web Worker (`src/phrases/reading.worker.ts`; never on the main thread, building the dictionary freezes the page); its dictionary loads lazily from jsDelivr, so no key or server is involved. A typed reading is never overwritten.
- To restart everyone's progress, raise `PROGRESS_RESET_ID` in `src/sync.ts`. Each device clears once and the server drops records without the matching `resetId`. Passwords and captured phrases stay. Merging means deleting only on the server would not work.
- The app installs as a PWA: `public/manifest.webmanifest`, `src/sw-template.js` and the `serviceWorker` plugin in `vite.config.ts`, which fills the precache list. The page is network-first so a push shows up at once; hashed files are cache-first. Supabase and word audio are never cached.
- Adding a tab means changing the phone `nav` column count in `src/style.css` too (`src/nav.test.ts` guards this).
- Hiragana and katakana are separate: `#/kana/{hiragana,katakana}` quizzes and `#/kana/chart/{hiragana,katakana}` charts. Old `#/kana` and `#/kana/chart` fall back to hiragana. `?mode=round` asks each kana in range once: correct removes it, wrong sends it to the back. The Korean spelling is 가타카나.
- DOM tests cannot verify CSS layout; inspect new screens in a browser when possible.
- Pass JavaScript to PowerShell-launched Node through a here-string/stdin or a file; inline quoting may strip string delimiters.
